# Native Library Input Cannot Be Used

Title: varies
Family: unsafe

## Explanation

A native library's link inputs come from its `[native-libraries]` table in `Baton.toml` or from `doriac` link flags. This error means one of them cannot be used for the platform being built.

The title names the problem. A framework is a macOS form and links on no other platform. A library linked statically on macOS links by its `lib<name>.a` file, and none of the library's search paths holds it. A runtime file, which is placed beside the program so the program can load it, does not exist, or two runtime files have the same file name.

## Fix

Give a framework only in the library's `macos` entry. For a static library on macOS, add the directory that holds the archive to `search-paths`, or pass `--link-search <library>=<directory>` or `--link-file <library>=<path>`. Correct a runtime file's path, or rename one of two files that share a name.

## Example

No program shows this code on its own: `doriac check` and `baton check` accept the program, and the code is reported when the program is compiled for the native target, by `doriac compile`, `doriac run`, `baton build` or `baton run`. A user meets it at the first declaration of an `extern "C"` block marked `#[Library]` whose inputs this platform cannot use.
