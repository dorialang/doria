# Shared Ownership Count Overflowed

Title: fixed
Family: runtime

## Explanation

A shared value counts its owning references. `share()` adds one, `acquire()` on a weak reference adds one when the value is still alive, and each access object from a `WritableSharedReference<T>` holds one. This panic means the count was at its maximum and the program asked for another owner.

The maximum is larger than the number of references a program can keep in memory, so a program that releases its references does not reach it.

## Fix

Hold fewer owning references to the value at one time. Look for a loop that calls `share()` and keeps every result, and let the references that are no longer needed go out of scope.

## Example

No program raises this code on demand: the count holds more owners than a program can keep in memory, so the limit is out of practical reach. A program could meet it only by holding an extreme number of owning references to one value at the same time.
