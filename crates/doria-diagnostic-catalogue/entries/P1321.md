# Mixed Value Does Not Have Unique Ownership

Title: fixed
Family: runtime

## Explanation

A `mixed` value is a box that holds a claim on its payload. Several boxes can hold claims on the same payload: an owning binding such as `mixed $item = $items[$index]` gives `$item` a box and a claim of its own and leaves the element in the collection.

A move-type payload, such as a class instance, can be taken out of a `mixed` only by the box that holds the last claim. This panic means the program narrowed a `mixed` to a move type and passed it to a `take` parameter, or consumed it with `match (take $value)`, while another box still held a claim on the same value.

## Fix

Give the `mixed` the only claim before taking from it. Remove the element from the collection with `removeAt` or `pop`, which hand back the owned element: `mixed $item = $items->removeAt(0);`. Any other `mixed` bound to the same element must have ended first; a standalone block `{ ... }` ends one early.

When the function only reads the value, declare its parameter without `take`. A readonly parameter borrows the payload and needs no unique claim.

## Example

```doria
class Document
{
    function __construct(string $name) {}
}

function archive(take Document $document): void
{
    echo $document->name;
}

function main(): void
{
    List<mixed> $items = [new Document("report")];
    mixed $item = $items[0];
    if ($item is Document) {
        archive($item);
    }
}
```
