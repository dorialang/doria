# Runtime Artifact Is Incompatible With This Compiler

Title: fixed
Family: compiler

## Explanation

The program compiled, and the Doria runtime library selected for linking was not built for this compiler, so the compiler refuses to link it. An executable linked against another runtime could behave differently from what the compiler checked.

Each runtime library has an identity record, a `.doria-runtime.json` file stored beside it. The compiler compares the record with what it expects: the record format, the ABI version, the target platform, the build profile, the revision, and the size and SHA-256 of the library. This code means that one of them differs, or that the record cannot be read or is incomplete. The `Note` lists the fields that differ, and the developer details give the path of the selected library, where it was selected from, and the expected and found value of each field.

## Fix

Use a compiler and a runtime library from the same build. If the `DORIA_RT_PATH` environment variable is set, unset it so the compiler uses the runtime it ships with, or point it at a runtime library built from the same revision as this compiler. Otherwise reinstall or refresh the Doria toolchain so that `doriac` and its runtime are replaced together.

When a runtime library is copied or replaced by hand, move the library and its `.doria-runtime.json` file together.

To see the selected path and the values that differ, run the command again with `--diagnostic-format json` and read the `developerDetails` field, or set `DORIA_DIAGNOSTIC_DEBUG=1`.

## Example

No program raises this code on demand: it depends on which runtime library is installed or selected on the machine, and the program plays no part in it. A user meets it when compiling or running any program after one half of the toolchain was updated without the other, or with `DORIA_RT_PATH` pointing at a runtime from another build.
