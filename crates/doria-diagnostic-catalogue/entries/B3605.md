# PHP Native Companion Library Is Unavailable

Title: fixed
Family: compiler

## Explanation

A program compiled with `--target php` that contains unsafe code could not load its native companion library, so it stopped with exit status 1. Unsafe code runs as native code: the compiler builds it into a library named after the generated PHP file, `<name>.native.so`, `.dylib` or `.dll`, and writes a `<name>.native.json` sidecar describing it, beside the PHP file. The generated program checks the sidecar and loads the library through PHP's FFI extension before it first runs unsafe code.

The report is printed by the generated program when it runs. Its `Why` section gives one of three reasons: the library or its sidecar is missing or unreadable; the library or its sidecar does not match the generated program; or PHP could not load the library on this host.

## Fix

Deploy the generated PHP file together with the `.native` library, its `.native.json` sidecar and the `.doria-runtime` directory the compiler wrote beside it, keeping their names and relative positions, on a machine of the same operating system and architecture as the one that compiled it. The native libraries the program links must be installed there too. After recompiling, replace all of them together.

## Example

No program raises this code on demand: the compiler never reports it, and it depends on the files deployed beside the generated program. A user meets it when running generated PHP that was copied without its companion library or sidecar, or with ones built for a different version of the program.
