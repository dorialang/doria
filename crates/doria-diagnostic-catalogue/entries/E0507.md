# Null-Safe Access Needs A Nullable Value With Members

Title: varies
Family: nullability

## Explanation

`?->` reads a member when its receiver is present and gives `null` when the receiver is `null`. This error means the receiver has a type that is never `null`, so `?->` has nothing to guard against.

The code is also raised for `->` or `?->` on a nullable number, `bool`, `string` or collection, such as `?int`, `?string` or `?List<int>`. Such a value is narrowed to non-null before its members are used.

## Fix

Use `->` when the receiver is never `null`. If the receiver is meant to be optional, declare it with a nullable type such as `?Token`.

For a nullable `string` or collection, test for `null` first and use `->` inside the branch, or supply a fallback with `??` before the access: `($name ?? "")->length`.

## Example

```doria
class Token
{
    function __construct(string $value) {}
}

function main(): void
{
    let $token = new Token("found");
    echo $token?->value ?? "none";
}
```
