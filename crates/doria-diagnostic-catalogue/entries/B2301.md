# PHP Target Cannot Preserve Collection Or Shared Ownership

Title: varies
Family: compiler

## Explanation

The program is valid, and the `php` target cannot reproduce one of its collection operations or shared-ownership values exactly, so the compiler stops before it writes any PHP.

The compiler raises this code for a `foreach` with a `writable` element binding over a collection, for an indexed read of a `Set`, for some properties and methods of `List`, `Dictionary`, `Set`, typed arrays and `Bytes`, for some `Set::` and `Bytes::` companion calls, and for a shared-ownership value whose payload the `php` target cannot hold, such as a class instance created with `shared new`.

The report marks the operation. For a shared-ownership value the title says so. For a collection operation the title is `Backend Error`, and the text that names the operation is in the developer details.

## Fix

Compile for the native target, which is the default, or for `--target debug`. Both keep Doria collections and shared ownership exactly.

To read which operation was refused, run the command again with `--diagnostic-format json` and read the `developerDetails` field, or set `DORIA_DIAGNOSTIC_DEBUG=1`.

## Example

No program raises this code on demand: checking never reports it, because the program is valid Doria. A user meets it only when compiling with `--target php` a program that uses a collection operation or a shared-ownership value the `php` target cannot keep exact.
