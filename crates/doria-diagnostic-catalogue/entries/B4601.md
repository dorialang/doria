# PHP Target Cannot Order Or Hash Enum Values Yet

Title: fixed
Family: compiler
Availability: planned

## Explanation

The program is valid, and the `php` target cannot yet reproduce one of its enum core operations, so the compiler stops before it writes any PHP. A Copy enum is `Equatable`, `Hashable` and `Comparable` when its payloads are (Decision 0096): its cases order by declaration, then by their payloads from left to right. Generating PHP for that order and hash is part of Doria. This compiler does not implement it yet.

The compiler raises this code for `hash` or `compare` on an enum value in generic code, and for an enum used as a `Set` element, a `Dictionary` key, a `SortedSet` element, a `SortedDictionary` key or a `PriorityQueue` element. Equality of enum values, `equals`, works in PHP output.

The report marks the operation. Its text, which names it, is in the developer details.

## Fix

Compile for the native target, which is the default, or for `--target debug`. Both order and hash enum values exactly.

To read which operation was refused, run the command again with `--diagnostic-format json` and read the `developerDetails` field, or set `DORIA_DIAGNOSTIC_DEBUG=1`.

## Example

No program raises this code on demand: checking never reports it, because the program is valid Doria. A user meets it only when compiling with `--target php` a program that orders or hashes an enum value or keys a collection by an enum.
