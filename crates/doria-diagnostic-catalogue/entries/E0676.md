# Build Plan Cannot Be Used

Title: varies
Family: projects

## Explanation

A build plan is the JSON file that Baton writes for a project and hands to the compiler. It names the project's packages, their source files and namespace mappings, their dependencies, and the target to check or build. This error means the compiler cannot use the plan it was given.

The title and the message say what is wrong. The plan could not be read, is not valid JSON, or has a missing or unknown field. Its schema version or its Doria edition is one this compiler does not accept. Or its contents contradict each other: a binary target has no entry source, a package or a source file is listed twice, or a package depends on a package that the plan does not list.

Baton reads `Baton.toml` and reports the mistakes it finds there under its own codes, before the compiler runs.

## Fix

In a project, run the `baton` command again. Baton writes the plan anew from `Baton.toml` and the source folders on every command.

A schema version or an edition that the compiler does not accept means the plan was written for a different release of the compiler. `baton doctor` reports the Baton version and the `doriac` version in use.

When the plan was written by hand or by another tool, correct the field the message names. Field names are camelCase, and a field the compiler does not know is rejected.

## Example

No single source file raises this code: it is reported for the build plan as a whole, before the compiler reads any source file, and the report points into the plan file. A user meets it when a plan is passed to `doriac` with `--build-plan`, by Baton or by hand.
