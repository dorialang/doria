# Weak Ownership Count Overflowed

Title: fixed
Family: runtime

## Explanation

A shared value counts its weak references. Each `createWeakReference()` adds one until that weak reference is destroyed. This panic means the count was at its maximum and the program asked for another weak reference.

The maximum is larger than the number of references a program can keep in memory, so a program that releases its weak references does not reach it.

## Fix

Hold fewer weak references to the value at one time. Look for a loop that calls `createWeakReference()` and keeps every result, and let the references that are no longer needed go out of scope.

## Example

No program raises this code on demand: the count holds more weak references than a program can keep in memory, so the limit is out of practical reach. A program could meet it only by holding an extreme number of weak references to one value at the same time.
