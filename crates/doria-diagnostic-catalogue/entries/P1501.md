# Writable Shared Access Conflicted

Title: fixed
Family: runtime

## Explanation

A `WritableSharedReference<T>` allows many readonly accesses at the same time, or one writable access. This panic means `acquireReadonlyAccess` or `acquireWritableAccess` was called while an incompatible access to the same value was still active. The report says which combination was refused: writable while readonly is active, readonly while writable is active, or writable while writable is active.

An access stays active until its access object is destroyed, normally at the end of the block that declares it. All handles to one value share this state, so the earlier access may have been acquired through another handle made with `share()`.

## Fix

End the first access before acquiring the next. Put the first access in a standalone block `{ ... }` so that it ends at the closing brace.

When the same code reads and writes, acquire one writable access and use it for both. A writable access permits readonly operations too.

## Example

```doria
class Counter
{
    writable int $value = 0;
}

function main(): void
{
    let $shared = new WritableSharedReference(new Counter());
    let $reader = $shared->acquireReadonlyAccess();
    let writable $writer = $shared->acquireWritableAccess();
    $writer->value = 1;
    echo $reader->value;
}
```
