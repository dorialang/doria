# Checked Construct Could Not Be Compiled

Title: varies
Family: compiler

## Explanation

The program passed checking, and a later step could not build the compiler's internal representation of the program, which the native target, the `debug` target and `doriac run` need. The title and the label of the report name the construct the compiler stopped at.

Most places that raise this code are safeguards inside the compiler. They fire when a later step meets something that checking is meant to rule out, such as a call with the wrong number of arguments or a value of another type than the one recorded. That is a defect in the compiler.

A few places describe a valid construct in a form that compilation does not accept, such as a nullable value or a collection stored directly in a `mixed` variable.

## Fix

Read the title and the marked code. When they describe a value the program stores in `mixed`, change that statement. For a nullable value, test it against `null` first and store it inside the branch where it is known to be present. For a collection, keep it in a variable of its own type.

When they describe a state inside the compiler, reduce the program to the smallest file that still shows the error and report it to the Doria project with the output of `--diagnostic-format json`.

## Example

No program raises this code on demand: `doriac check` accepts every program that reaches it, and it is reported only when that program is compiled or run. A user meets it at `doriac compile` or `doriac run`, under a title that names the construct the compiler stopped at.
