# Implicit Constructor Cannot Hide A Throwing Initializer

Title: fixed
Family: errors

## Explanation

A property initializer runs each time the class is constructed, so a checked error raised by an initializer leaves through the constructor. A constructor that lets a checked error out must list it in a `throws` clause.

A class with no `__construct` has an implicit constructor, which declares no `throws`. This error means a property initializer of such a class can raise a checked error that no constructor declares.

## Fix

Declare `__construct` in the class and list the initializer's errors in its `throws` clause, as in `function __construct() throws ConfigError`. Code that writes `new Settings()` then catches the error or declares it in turn.

If construction should never fail, initialize the property with a value that raises nothing, or call a function that catches the error and returns a fallback.

## Example

```doria
class ConfigError implements Error
{
    function __construct(string $message)
    {
    }
}

function loadName(): string throws ConfigError
{
    throw new ConfigError("no name configured");
}

class Settings
{
    string $name = loadName();
}

function main(): void
{
    let $settings = new Settings();
    echo $settings->name;
}
```
