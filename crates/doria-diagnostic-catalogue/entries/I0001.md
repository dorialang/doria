# Internal Compiler Error

Title: fixed
Family: compiler

## Explanation

The compiler checked the program and then found that its own record of the program was missing or inconsistent, so it stopped before producing output. This is the general internal error, used where no more specific code applies.

The compiler raises it when its record of the traits a class composes with `uses` does not match the class, or when a declaration carries a `where (...)` condition and the record of which callables that condition admits is missing.

This is a defect in the compiler. No mistake in the source of a program produces it.

## Fix

Report it to the Doria project. Run the command again with `--diagnostic-format json` and include the output: the `developerDetails` field holds the compiler's own description of the failure, and the notes give the toolchain version and build commit.

Send the smallest program that still shows the error. The report marks the class or declaration the compiler was working on, so start there and remove the code around it.

## Example

No program raises this code on demand: it appears only when the compiler reaches a state that a correct compiler never reaches, so a program that raises it today stops raising it once the defect is corrected. A user meets it when compiling or running a program whose classes compose traits with `uses` or whose declarations carry `where (...)` conditions.
