# Trait Member Depends On A Class Hierarchy

Title: varies
Family: interfaces

## Explanation

A trait holds members that a class receives through `uses`. A trait has no parent class and no place of its own in a class hierarchy. The class that composes it decides both.

This error means the trait declares something that needs a hierarchy: a `__construct` or `__destruct` method, a method marked `open` or `override`, or an expression that uses `parent::`.

## Fix

Move the member into the class that composes the trait. A class declares its own constructor and destructor, marks its own methods `open` or `override`, and calls `parent::` from its own methods.

When the trait needs behavior that the class supplies, declare a method requirement in the trait, which is a signature that ends with `;`, and call it through `$this`. Every class that composes the trait then supplies that method.

## Example

```doria
trait Describes
{
    function describe(): string
    {
        return parent::describe();
    }
}

class Note
{
    uses Describes;
}

function main(): void
{
    let $note = new Note();
    echo "created a note";
}
```
