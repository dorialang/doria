# Match Has No Single Result Type

Title: varies
Family: enums

## Explanation

A `match` produces one value, so its arms agree on one type. When the destination declares no type, as with `let`, the first arm sets the result type and every later arm must fit it. This error means an arm produces a different type. Doria does not widen numbers or fall back to `mixed`.

Arms may mix a type `T` with `null`; the result is then `?T`. A `match` whose arms are all `null` has no type to take and is reported under this code.

## Fix

Make every arm produce the same type. To turn a number into text, use interpolation: `"{$count}"`.

When every arm is `null`, declare the destination with a nullable type, as in `?string $name = match ($count) { ... };`.

## Example

```doria
function main(): void
{
    let $count = 1;
    let $label = match ($count) {
        1 => "single",
        default => 0,
    };
    echo $label;
}
```
