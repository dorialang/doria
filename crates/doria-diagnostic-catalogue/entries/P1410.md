# Program Argument Is Not Valid UTF-8

Title: fixed
Family: runtime

## Explanation

The program was started with a command-line argument that is not valid UTF-8. Arguments reach `main` as `string` values, and a `string` is always valid UTF-8, so the program ends before `main` runs.

Every program checks its arguments this way, including one whose `main` takes no parameters.

## Fix

Start the program with arguments encoded as UTF-8. The usual cause is a file name in another encoding. The change belongs where the program is started; nothing in the source changes this panic.

To hand the program arbitrary bytes, put them in a file and read it with `read_file_bytes`, which performs no UTF-8 validation.

## Example

No program raises this code on demand: the arguments come from the command line that starts the program, so the panic depends on what the caller passes. A program meets it when it is started with an argument that is not valid UTF-8, such as a file name in another encoding.
