# C Boundary Conversion Is Out Of Range

Title: fixed
Family: runtime

## Explanation

`CLong::from`, `CUnsignedLong::from`, `CChar::from`, `CSize::from`, `CPointerDifference::from` and `CWideChar::from` convert an integer to the C type a foreign function declares. Each of these types has the width and signedness the C type has on the target the program runs on: `long` is 32-bit on Windows and 64-bit on Linux and macOS, `char` is unsigned on Linux aarch64, and `wchar_t` is 16-bit on Windows. This panic means the value is outside that range on this target, so the same program can run on one platform and panic on another: `CLong::from(3000000000)` fits on Linux and panics on Windows.

## Fix

Use `tryFrom` when the value can be out of range, and decide what the program does when it returns `null`: `?CLong $length = CLong::tryFrom($count);`.

If the C function accepts a wider type, bind that type in the declaration instead, such as `int64` for `long long`.

## Example

```doria
use Doria\Std\Ffi\CUnsignedLong;

function main(): void
{
    let $length = CUnsignedLong::from(-1);
    echo $length == CUnsignedLong::from(0);
}
```
