# Checked Errors Escape Without A Declaration

Title: varies
Family: errors

## Explanation

A function, method or constructor declares every checked error that can leave it. The errors come from its own `throw` statements and from the functions it calls. This error means an error can leave the body, and the `throws` clause is missing or does not list it.

`main` may omit its `throws` clause. The I/O errors of built-in operations such as `echo`, `Doria\Std\Io\IoError` and `Doria\Std\Io\InvalidUtf8Error`, need no declaration.

A destructor is stricter. No checked error may leave `__destruct`, and that includes those I/O errors. A C-callable function, an `extern "C" function` with a body, is equally strict, because C receives only its return value.

## Fix

Catch the error in the body with `try` and `catch`, or add it to the `throws` clause after the return type: `function show(string $text): void throws ParseError`. Each caller then catches or declares it in turn.

In `__destruct` or a C-callable function, catch every error inside the body, for example with `catch (Doria\Std\Io\IoError $error)` around `echo`. `catch (Error)` handles any checked error.

## Example

```doria
class ParseError implements Error
{
    function __construct(string $message)
    {
    }
}

function parse(string $text): int throws ParseError
{
    if ($text == "") {
        throw new ParseError("empty input");
    }
    return $text->length;
}

function show(string $text): void
{
    echo parse($text);
}

function main(): void
{
    show("abc");
}
```
