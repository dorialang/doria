# Unsafe Code Is Not Available Yet

Title: varies
Family: unsafe
Availability: planned

## Explanation

Unsafe code and the foreign function interface are part of Doria. This compiler does not implement it yet in full. It checks every unsafe and foreign form: `declare` directives and the unsafe policy, `Platform`, `unsafe` contexts, unsafe functions, `extern "C"` declarations, C-callable functions, C function pointer types, foreign structs and unions, pointer operations and C boundary conversions. For the native target it builds C boundary conversions, pointer operations, calls to the platform C runtime and to native libraries, variadic ones included, linked from `[native-libraries]` or the `--link-library` flags, foreign structs and unions and their nullable forms as locals, parameters, results, pointer targets, instance and static properties, constants, enum payloads, elements of `T[]` and collections and the parameters, results and captures of closures and function types, foreign structs and unions as `mixed` values, foreign structs and unions by value across the C boundary, pointers to region storage, `CString` and `Utf16String` values and their pointers, calls through C function pointer values, C-callable functions, whose names are C function pointer values that C calls on the program's thread, `errno` and `GetLastError` capture with `ForeignCall::lastSystemCode`, fixed-length array fields of scalar and nullable pointer elements read, supplied and assigned as regions, typed array regions over numbers, `bool`, enum cases, pointers, nullable pointers, foreign structs and unions and other plain Copy values, which the interpreter also runs, regions over memory a foreign library owns, and handles of class values and shared references. It cannot yet build typed array regions over strings, classes, collections, `?Name` values of foreign structs and unions and other element types that own or share a value, pointers to properties and elements, or foreign structs and unions in other type arguments. The debug target runs unsafe code through the native companion library. PHP output runs unsafe code there when that code calls no Doria code, writes no output and passes only numbers, `bool` values and strings. PHP output does not yet build other unsafe code, C-callable functions, or pointers, foreign structs and unions, foreign strings and foreign layouts in safe code. The program checks; when it is built, the compiler names each such form and stops.

The title names the form, such as `Foreign Aggregates Cannot Be Built Here Yet` or `Pointers Cannot Be Built For PHP Output Yet`.

## Fix

When the title names PHP output, build the program with `--target native`, or run it with `--target debug`; both build the form. For any other form, keep the code for a compiler that implements it, or move the foreign bindings out of the program and reach the same work through the standard library, such as `Doria\Std\Io` for files and processes.

## Example

No program shows this code on its own: `doriac check` and `baton check` accept the program, and the code is reported when the program is built, by `doriac compile`, `doriac run`, `baton build` or `baton run`. A user meets it at a foreign struct as the type argument of a generic class, or at a pointer in a program compiled with `--target php`.
