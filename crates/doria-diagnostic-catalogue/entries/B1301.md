# Backend Error

Title: fixed
Family: compiler

## Explanation

The program is valid, and the `php` target cannot reproduce one of its integer operations exactly, so the compiler stops before it writes any PHP. Doria integers have fixed widths and checked overflow. PHP has one signed 64-bit integer type and turns a value outside that range into a float.

The compiler raises this code for an integer literal outside PHP's signed integer range, and for integer arithmetic, a bitwise operation, `++` or `--`, a compound assignment such as `+=`, or a conversion such as `Int8::from` whose integer type the `php` target cannot establish.

The report marks the operation. Its text, which names the operation and the reason, is in the developer details.

## Fix

Compile for the native target, which is the default, or for `--target debug`. Both keep Doria integer behavior exactly.

If the program must be compiled to PHP and the marked code is an integer literal, keep the literal within the signed 64-bit range.

To read which operation was refused and why, run the command again with `--diagnostic-format json` and read the `developerDetails` field, or set `DORIA_DIAGNOSTIC_DEBUG=1`.

## Example

No program raises this code on demand: checking never reports it, because the program is valid Doria. A user meets it only when compiling with `--target php` a program that contains an integer operation PHP cannot reproduce exactly.
