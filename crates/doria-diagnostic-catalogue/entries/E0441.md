# Operand Types Do Not Match

Title: varies
Family: types

## Explanation

Both operands of an arithmetic operator or a comparison must have the same numeric type. Doria never widens a number: an `int` and a `uint8` cannot be added or compared, and neither can a `float` and an `int`. A compound assignment such as `+=` and the two endpoints of a range follow the same rule.

This code is also raised when `<`, `<=`, `>` or `>=` is applied to class values. Classes have no ordering. Pointers and C boundary values such as `CLong` have neither arithmetic nor ordering; they compare with `==` and `!=` only.

## Fix

Convert one operand so both have the same type. Between integer types, use a companion `from` call: `$total > Int::from($limit)`. `from` panics when the value does not fit the target type, so convert toward the wider type. Between an `int` and a `float`, use `Int::toFloat($count)` or `Float::toInt($ratio)`.

To order class values, compare a property of each, such as `$old->major < $new->major`. Convert a C boundary value with a fixed-width companion, as in `Int64::from($length)`, and move a pointer with `offset` or `byteOffset`.

## Example

```doria
function main(): void
{
    int $total = 300;
    uint8 $limit = 200;
    let $over = $total > $limit;
}
```
