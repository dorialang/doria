# Invalid Trait Composition

Title: varies
Family: interfaces

## Explanation

A class or a trait receives the members of other traits with `uses`. This error means the composition cannot be resolved into one set of members.

The most common cause is a conflict: two traits supply a member with the same name, and nothing chooses between them. The second cause is a requirement: a trait declares a method signature that ends with `;`, and the composing class does not supply that method, or supplies it with a different signature.

The remaining causes are mistakes in the adaptation block that follows `uses`. An adaptation names a trait that the same `uses` does not list, names a member that is not a method with a body, declares an alias twice, gives an alias the name of another member or of the method it renames, excludes the trait it selects, or writes `public`, `private` or `protected` after `as`.

## Fix

For a conflict, choose one method with `insteadof` in a block after the trait list: `uses JsonFormatting, TextFormatting { JsonFormatting::format insteadof TextFormatting; }`. To keep the other method as well, give it a new name in the same block: `TextFormatting::format as formatText;`.

For a requirement, declare the method in the class with the same signature that the trait declares.

For an adaptation, name a trait listed in the same `uses` and a method that trait defines with a body, and give every alias a name that no other member has. The only access change an adaptation makes is `as internal`.

## Example

```doria
trait JsonFormatting
{
    function format(): string
    {
        return "json";
    }
}

trait TextFormatting
{
    function format(): string
    {
        return "text";
    }
}

class Message
{
    uses JsonFormatting, TextFormatting;
}

function main(): void
{
    let $message = new Message();
    echo $message->format();
}
```
