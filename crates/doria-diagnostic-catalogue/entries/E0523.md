# Key Or Element Type Cannot Be Hashed Or Ordered

Title: varies
Family: collections

## Explanation

`Set` and `Dictionary` find their elements and keys by hash, so the element or key type must be `Hashable`. `SortedSet`, `SortedDictionary` and `PriorityQueue` keep their contents in order, so the element or key type must be `Comparable`. This error means the type argument does not meet the requirement.

Integers, `bool` and `string` meet both. `float` meets neither, because NaN and signed zero leave it without a total order. A nullable type such as `?int` meets neither. A class meets a requirement when it implements the interface.

## Fix

Use an integer, `bool` or `string` as the key or element type.

To use a class as a key or element, declare it `implements Equatable<Key>, Hashable` and write `equals` and `hash`. For a sorted collection or a `PriorityQueue`, declare `implements Comparable<Key>` and write `compare`.

## Example

```doria
function main(): void
{
    Dictionary<float, string> $labels = [];
    echo $labels->count;
}
```
