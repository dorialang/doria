# Internal Compiler Error

Title: fixed
Family: compiler

## Explanation

The compiler could not turn a test expectation that passed checking into executable code. This code covers `expect` from `Doria\Std\Test` and its matchers, such as `toEqual`, `toContain`, `toBeNull` and `toThrow`, and the `AssertionError` that reports a failed expectation. It means that a value under test or an expected value has no compiled form or a different type from the one its matcher needs, for a comparison, a `null` test, a string, a collection, a dictionary key or an enum, or that the `AssertionError` class is not available to the compiled program.

This is a defect in the compiler. No mistake in the source of a program produces it.

## Fix

Report it to the Doria project. Run the command again with `--diagnostic-format json` and include the output: the `developerDetails` field holds the compiler's own description of the failure, and the notes give the toolchain version and build commit.

Send the smallest test that still shows the error. The report marks the expectation or the value under test when it has a location for it, so keep that expectation and the declarations it uses, and remove the tests around it.

## Example

No program raises this code on demand: it appears only when the compiler reaches a state that a correct compiler never reaches, so a program that raises it today stops raising it once the defect is corrected. A user meets it when the tests of a project are compiled or run, at an expectation written with `expect`.
