# C Called Doria From Another Thread

Title: fixed
Family: runtime

## Explanation

An `extern "C" function` is a Doria function that C calls through its address, such as a callback a C library stores. Doria code runs on one thread, and its values are not shared between threads. When C calls the function on any other thread, for example a thread a C library starts for its own work, the call panics before the function's body runs.

## Fix

Have the C library call the function on the thread that runs the program, as a library does when it calls back during a call the program made. When a library delivers its callbacks on its own threads, keep the work on the C side of the boundary, or use the library's option to deliver them to the calling thread.

## Example

No program raises this code on demand on every platform: it needs a thread that C creates, which one source can only start through `pthread_create` on Linux and macOS and `CreateThread` on Windows. A user meets it when a C library calls a Doria callback from a thread of its own, such as an audio or file-watching thread.
