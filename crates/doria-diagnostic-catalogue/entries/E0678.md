# Project Cannot Be Assembled From Its Build Plan

Title: varies
Family: projects

## Explanation

A build plan is the JSON file that Baton writes for a project and hands to the compiler. It names the project's packages, their folders, namespace mappings, source files and dependencies. This error means the plan is well formed, and the packages and files it names do not fit together.

The message names the problem. A package folder does not exist or is not a directory. A folder named by a namespace mapping is missing, lies outside its package, or is spelled with different casing from the folder on disk, or the same mapping is listed twice. Two listed source files are the same file, or their paths differ only in casing. An `include` reaches a file under a name that the plan gives to a different file. Packages depend on one another in a cycle.

Baton checks `Baton.toml`, the source folders and the dependencies before it writes a plan, and reports what it finds under its own codes.

## Fix

In a project, correct the package, folder or file that the message names and run the `baton` command again. Baton writes the plan anew on every command. A namespace mapping is an entry of `[autoload.namespaces]` or `[autoload-dev.namespaces]` in `Baton.toml`, and a dependency is an entry of `[dependencies]` or `[dev-dependencies]`. Remove one dependency of a cycle to break it.

When the plan was written by hand or by another tool, correct the entry the message names.

## Example

No single source file raises this code: it is reported for the build plan of a project, before any source file is checked, and the report points at the plan file. A user meets it when a plan is passed to `doriac` with `--build-plan`. For a project built through Baton, the same mistakes are normally reported first by Baton.
