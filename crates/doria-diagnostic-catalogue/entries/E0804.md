# Native Library Has No Link Input

Title: fixed
Family: unsafe

## Explanation

An `extern "C"` block marked `#[Library("name")]` binds functions of a native library, and the program's code calls into it, so the program links that library. Source names the library; the package's `Baton.toml` says how to link it on each platform, in a `[native-libraries.name]` table. This error means the compiler has no link input for that library on the platform it is building for: `Baton.toml` has no entry for this platform, or the compiler runs directly and no `--link-library` flag names the library.

A library that no emitted code calls needs no input, so a platform branch that is not built for this target does not need one.

## Fix

Add an entry for the platform to the library's table in `Baton.toml`, such as `macos = { system = "z" }`, `linux = { pkg-config = "zlib" }` or `windows = { library = "zlib", search-paths = ["native/windows/lib"] }`. When running `doriac` directly, pass the input with `--link-library zlib=z`, and add `--link-search zlib=<directory>` when the library is outside the default search.

## Example

No program shows this code on its own: `doriac check` and `baton check` accept the program, and the code is reported when the program is compiled for the native target, by `doriac compile`, `doriac run`, `baton build` or `baton run`. A user meets it at the first declaration of an `extern "C"` block marked `#[Library("zlib")]` when nothing gives `zlib` a link input.
