# Expectation Operand Has The Wrong Type

Title: varies
Family: testing

Example source: development

## Explanation

Each matcher accepts certain types. `toBeTrue` and `toBeFalse` need a `bool`. `toBeNull` needs a nullable or `mixed` value. `toStartWith` and `toEndWith` need strings. `toContain` works on a string, a typed array, a `List`, a `Set`, a `SortedSet`, a `PriorityQueue` or a `Deque`. `toHaveKey` and `toHaveValue` need a `Dictionary` or a `SortedDictionary`, `toHaveCount` takes an `int`, and `toThrow` needs a function value that has no parameters.

This error means the value given to `expect`, or the argument given to the matcher, has a type that the matcher does not accept. Doria performs no implicit conversions, so a `string` or an `int` is never accepted where a `bool` is needed. `fail` raises this code when its message is not a `string`.

## Fix

Choose the matcher that fits the value, or expect an expression of the type the matcher needs. For a condition, write the comparison: `expect($name == "Ada")->toBeTrue();`. For a string, use `toEqual`, `toContain` or `toBeEmpty`, as in `expect($name)->not->toBeEmpty();`.

For a dictionary, use `toHaveKey` or `toHaveValue`. For `toThrow`, wrap the call in a closure: `expect(fn() => parse(""))->toThrow();`. A closure passed to `toThrow` takes one readonly parameter whose type is `Error` or implements it, and returns `void`.

## Example

```doria
use Doria\Std\Test\{it, expect};

it("has a name", function (): void {
    let $name = "Ada";
    expect($name)->toBeTrue();
});
```
