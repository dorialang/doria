# Declaration In Another Package Is Not Visible

Title: varies
Family: projects

## Explanation

A source file can use the declarations of its own package and the declarations that the direct dependencies of that package expose. This error means the file names a declaration of another package that it is not allowed to see. The title says which of three cases applies.

The package is a dependency of a dependency and is not listed in the `Baton.toml` of the package that uses it. The package is listed under `[dev-dependencies]`, which only development source such as tests can use, and the file is ordinary source. Or the declaration is marked `internal`, which keeps it inside the package that declares it.

## Fix

For a dependency of a dependency, add the package to `[dependencies]` in `Baton.toml`. `baton add` does this, as in `baton add <package> --source path --path <folder>` for a package in a local folder.

For a development dependency, move the code that uses it into the project's test sources, the folders mapped under `[autoload-dev.namespaces]`, or list the package under `[dependencies]` when ordinary source needs it.

For an `internal` declaration, use a declaration that the package exposes. If the package is yours, remove `internal` from the declaration.

## Example

No single source file raises this code: it takes a project with at least one dependency, checked with a command such as `baton check`. The development dependency case is reported by `baton test`, which adds the development dependencies to the compilation. A function named this way is reported a second time where it is called, as E0309.
