# Checked Program Could Not Be Run

Title: varies
Family: compiler

## Explanation

The program passed checking, and a later step could not carry it out. The compiler raises this code in two situations, and the title of the report says which.

The first is the `debug` target, which runs the program inside the compiler and writes a record of its exit status and output. The run stopped on a fault in the compiler's internal representation of the program. This is a defect in the compiler.

The second is a shared-ownership handle, such as the result of `shared new`, used in a form that compilation does not accept. The handle is stored in a `mixed` variable, or the compiler has no compiled form for the handle or for the value it holds.

## Fix

For a shared-ownership handle, keep the handle in a variable, property or collection of its own type, such as `SharedReference<Node>` or `List<SharedReference<Node>>`, and do not store it in `mixed`.

For a failure of the `debug` target, compile the program for the native target, which is the default and does not run the program during compilation. Then reduce the program to the smallest file that still shows the error with `--target debug` and report it to the Doria project with the output of `--diagnostic-format json`.

## Example

No program raises this code on demand: `doriac check` accepts every program that reaches it, and it is reported only when that program is compiled or run. A user meets it when compiling with `--target debug`, or when compiling or running a program that stores a shared-ownership handle in a `mixed` variable.
