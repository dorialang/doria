# Enums With Payloads Cannot Be Collection Keys Yet

Title: fixed
Family: collections
Availability: planned

## Explanation

A Copy enum whose payloads are all `Hashable` is `Hashable`, and one whose payloads are all `Comparable` is `Comparable` (Decision 0096). Using such an enum with payload cases as a `Set` element, a `Dictionary` key, a `SortedSet` element, a `SortedDictionary` key or a `PriorityQueue` element is part of Doria. This compiler does not implement it yet: those collections store each key in one machine word, and an enum with payload cases is wider.

An enum without payloads already works in every one of these collections. An enum with payloads already works everywhere else, including `List`, `Dictionary` values, `equals`, `hash` and `compare`, and generic code constrained by `Equatable`, `Hashable` or `Comparable`. The compiler also reports this code when generic code uses a type parameter as a key or element and a call gives it an enum with payloads.

## Fix

Key the collection by a value that identifies the case and its payload: a `string` built from them, an `int`, or a class that implements `Equatable`, `Hashable` and, for an ordered collection, `Comparable`. Keep the enum values in a `List` or as `Dictionary` values.

## Example

```doria
enum Cell
{
    case Empty;
    case Glyph(string $text);
}

function main(): void
{
    Set<Cell> $cells = Set::from([Cell::Empty]);
    echo $cells->count;
}
```
