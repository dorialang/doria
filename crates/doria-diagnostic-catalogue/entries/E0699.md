# Invalid Attribute Processor Protocol

Title: fixed
Family: projects

## Explanation

An attribute processor is a program that a project names under `[processors]` in `Baton.toml`. During a build it receives a request that describes the attributes applied in the project, and it answers with a response that may hold diagnostics and generated `.doria` source files. The request and the response are JSON documents in a fixed, versioned form.

This error means a request or a response does not follow that form, and the message says how. The document is not valid JSON, has a missing or unknown field, or has a schema version the compiler does not know. A response answers a different request. A generated source file has a path that is absolute, leaves the package, does not end in `.doria`, repeats another path or names a handwritten source file, or its content hash does not match its contents.

The same code covers the diagnostics a processor sends. Each has a code of the processor's own, a Title Case title, a message, and labels that lie inside a source file named in the request. A diagnostic that uses one of the compiler's codes or contains terminal control characters is refused.

## Fix

Correct the processor so that its response follows the protocol. Copy `graphFingerprint` from the request. Give each generated source a `relativePath` inside the package that ends in `.doria`, and a `contentHash` that is the SHA-256 hash of `contents` in hexadecimal. Give each diagnostic a code that the compiler does not use, and a title in Title Case.

When the processor belongs to another package, update that package or report the fault to its author.

## Example

No program raises this code on demand: Baton runs the processors of a project, checks each response itself and reports a faulty one under its own code. This code is reported only to a tool that uses the compiler as a library and hands a request or a response to its check of the protocol.
