# Source File Does Not Follow The Project Layout

Title: varies
Family: projects

## Explanation

In a project, `Baton.toml` maps namespace prefixes to source folders under `[autoload.namespaces]`, and under `[autoload-dev.namespaces]` for test sources. The mapping `"App\\" = "src/"` places `namespace App;` in `src/` and `namespace App\Models;` in `src/Models/`. The mapping `"" = "src/"` places a file without a `namespace` statement in `src/`. Folder names match the namespace segments exactly, including case.

This error means a source file is not in the folder its namespace names, or no mapping covers its namespace, or two mappings cover it equally well.

The same code covers the rule for types. A class, enum, interface or trait that is not marked `internal` is declared in a file named after it, `Welcome.doria` for `class Welcome`, and a file declares at most one such type. The entry file of a binary may have any name.

## Fix

Move the file to the folder its namespace names, or change its `namespace` statement to match the folder. When no mapping covers the namespace, add one to `[autoload.namespaces]` in `Baton.toml`, or use a namespace that begins with a mapped prefix. With the mapping `"App\\" = "src/"` and no mapping for the empty prefix, every file in `src/` needs a `namespace` statement, the entry file included.

For a type, rename the file after the type or the type after the file. When a file declares several types, give each its own file, or mark the helpers `internal`.

## Example

No single source file raises this code: the rules compare the namespace and the name of a file with the namespace mappings of its project, so the code is reported only when a project is checked, for example with `baton check`. A file checked alone with `doriac check` has no mappings to be compared with.
