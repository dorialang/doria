# Shared Ownership Allocation Failed

Title: fixed
Family: runtime

## Explanation

`shared new T(...)` and `new WritableSharedReference(...)` allocate a small record that tracks the owners of the shared value. This panic means the runtime could not get the memory for that record.

The program was out of memory at that expression. The memory is usually held elsewhere.

## Fix

Reduce the memory the program holds at one time. Let collections and objects that are no longer needed go out of scope, and work through large inputs in parts.

If the program creates shared values inside a loop that never ends, correct the loop.

## Example

No program raises this code on demand: the panic needs the machine to refuse a small allocation, which depends on the memory that is free at that moment. A program meets it where it creates a shared value while memory is exhausted.
