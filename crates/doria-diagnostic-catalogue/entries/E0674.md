# Invalid Package Identity

Title: fixed
Family: projects

## Explanation

Every package in a project has an identity of the form `vendor/package`, such as `acme/blog`. The compiler uses it to tell packages apart and to decide which declarations marked `internal` a source file may use. This error means the compiler was given an identity that is not in that form.

An identity has exactly two parts separated by one `/`. Each part has at least one character and uses only the lowercase letters `a` to `z`, digits, `-` and `_`.

## Fix

Give the package a lowercase `vendor/package` name, as in `name = "acme/blog"` under `[package]` in `Baton.toml`. Write capital letters in lowercase, and replace spaces and other punctuation with `-` or `_`.

A package that is not meant to be published may have a name of one part, such as `name = "hello"` with `publishable = false`. Baton gives it the identity `local/hello`.

## Example

No program raises this code on demand: Baton checks the package name in `Baton.toml` and reports a mistake there under its own code, and a build plan that names a package in another form is reported as E0676. This code is reported only to a tool that uses the compiler as a library and names a package to it directly.
