# Borrow-Bound Value Keeps Source In Use

Title: fixed
Family: ownership

## Explanation

Some values are views of another value and own nothing themselves: a `ByteRegion` of a `Bytes` value, or an object built through a `borrow` constructor parameter. While such a view is still going to be used, its source stays in use. A readonly view allows the source to be read. A writable view allows no other access to the source at all.

This error means the program changes the source, gives it away, or assigns it again while a view of it is used later. With a writable view, reading the source is an error as well.

## Fix

Finish with the view first. Move the statement that changes the source to after the last use of the view.

When the view must stay declared, put it in a block of its own and change the source after the block closes. When the later code needs only a few values from the view, copy them into variables before changing the source.

## Example

```doria
function main(): void
{
    writable Bytes $bytes = Bytes::allocate(4);
    let $view = $bytes->getRegion(0, 2);
    $bytes[0] = 1;
    echo $view[0];
}
```
