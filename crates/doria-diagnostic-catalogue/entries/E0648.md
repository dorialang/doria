# Function Value Does Not Match Its Function Type

Title: varies
Family: functions

## Explanation

A function type such as `function(int): string` fixes the number of parameters, the type and the `writable` or `take` mode of each one, and the return type. A function value fits only when all of these are the same. Doria performs no implicit conversions here, so a closure that returns `int` does not fit a type that returns `string`.

Two more rules apply. A closure that changes a captured variable is a `function writable(...)` value, and one that gives away a captured value is a `function once(...)` value; neither fits a plain `function(...)` type. A function value that can raise a checked error fits only a type whose `throws` clause covers that error. A nullable function value does not fit a type without `?`.

## Fix

Change the closure so that its parameters and its result agree with the declared type, or change the declared type. To return text from a number, use interpolation: `"score: {$score}"`.

When the closure needs writable or once invocation, declare that in the type, as in `function writable(): int`. When it can raise a checked error, add the error to the type's `throws` clause.

## Example

```doria
function main(): void
{
    function(int): string $label = fn(int $score) => $score * 2;
    echo $label(21);
}
```
