# PHP Native Runtime Dependency Is Unavailable

Title: fixed
Family: compiler

## Explanation

A program compiled with `--target php` could not load the Doria runtime library it depends on, so it stopped with exit status 1. The compiler publishes that library in a `.doria-runtime` directory beside the generated PHP file, together with an identity record. The generated program loads the library through PHP's FFI extension the first time it needs it, for work such as file and stream I/O.

The report is printed by the generated program when it runs. Its `Why` section gives one of six reasons: the PHP installation does not permit FFI; the library or its identity record is missing or unreadable; the library does not match the generated program; PHP could not load the library on this host; the library's storage layout cannot be represented by this PHP installation; or the library returned an invalid status.

## Fix

Deploy the generated PHP file together with the `.doria-runtime` directory the compiler wrote beside it, keeping their relative positions, on a machine of the same operating system and architecture as the one that compiled it. After recompiling, replace both.

When the reason is FFI, enable the PHP FFI extension for the way the program is run. When the reason is that the library does not match, the library or its record differs from the one this PHP file was compiled with. Copy the directory that was written with this PHP file.

When the reason is an invalid status, the report names the operation that failed. Report it to the Doria project with that text and the program.

## Example

No program raises this code on demand: the compiler never reports it, and it depends on the PHP installation and on the files deployed beside the generated program. A user meets it when running generated PHP that was copied without its `.doria-runtime` directory, or on a PHP installation where FFI is not enabled.
