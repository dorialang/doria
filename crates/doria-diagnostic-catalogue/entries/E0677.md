# Source File Cannot Be Loaded

Title: varies
Family: projects

## Explanation

To check a project the compiler loads every source file that Baton lists for the project's packages, and every file named by an `include` statement. This error means one of those files could not be loaded.

The title says why: the file is missing, the path names a directory, the path leads outside its package, the casing of the path differs from the name on disk, the file is not valid UTF-8, the file could not be read, or the path is not a valid path inside the package.

An `include` path is a string literal, relative to the folder of the file that contains the `include`. It stays inside the package, so an absolute path is rejected, and so is a path that leaves the package through `..`. For an `include`, the report marks the path.

## Fix

For an `include`, correct the path so that it names an existing file of the same package, spelled with the same uppercase and lowercase letters as on disk.

For a file in one of the project's source folders, save it as UTF-8 and make sure it can be read. If the file was removed or renamed, run the `baton` command again: Baton lists the source files anew on every command.

## Example

No single source file raises this code: a file checked alone with `doriac check` is the whole compilation, and an `include` in it is reported as E0681. A user meets this code when a project is checked or built, for example with `baton check`, for a project file that cannot be loaded or an `include` whose path does not lead to a file of the package.
