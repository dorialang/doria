# Conflicting Uses Of One Value

Title: varies
Family: ownership

## Explanation

A `writable` use of a value is exclusive: while it lasts, nothing else may read or change that value. Readonly uses may overlap each other. This error means a `writable` use overlaps another use of the same value.

Arguments are evaluated from left to right, and an earlier argument stays in use until the call returns. `report($counter, $counter->increment())` reads `$counter` for the first argument and then needs `writable` access to it for the second.

A variable that holds a result borrowed from an object, such as `let $engine = $car->getEngine();`, keeps `$car` in use until the last use of `$engine`.

Forming a pointer with `Ptr::to` or `MutPtr::to` keeps its place in use until the unsafe context it is formed in ends: readonly for `Ptr::to`, `writable` for `MutPtr::to`.

## Fix

Finish one use before the other begins. Compute the value in a statement of its own, store it in a local variable, and pass the variable: `let $next = $counter->increment();`.

When a local variable borrows from the object, move its last use before the change, or make the change first.

## Example

```doria
class Counter
{
    writable int $count = 0;

    writable function increment(): int
    {
        $this->count += 1;
        return $this->count;
    }
}

function report(Counter $counter, int $next): void
{
    echo "{$counter->count} then {$next}";
}

function main(): void
{
    let writable $counter = new Counter();
    report($counter, $counter->increment());
}
```
