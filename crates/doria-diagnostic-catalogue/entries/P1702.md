# Pointer Access Is Misaligned

Title: fixed
Family: runtime

## Explanation

`read` and `write` on a `Ptr<T>` or `MutPtr<T>` need an address that is a multiple of `T`'s alignment: 4 for `int32` and `float32`, 8 for `int64`, `float64` and pointers. The test runs in every profile before memory is touched. This panic means the address is not aligned, which happens when a pointer is moved with `byteOffset` into the middle of a value or is built from an address a C library documents as unaligned, such as a field in a packed network header.

## Fix

If the data is unaligned on purpose, use `readUnaligned` or `writeUnaligned`, which accept any address.

Otherwise find where the address came from. Move a typed pointer with `offset`, which counts whole elements, rather than with `byteOffset`.

## Example

```doria
use Doria\Std\Ffi\Ptr;

function main(): void
{
    unsafe {
        ?Ptr<int32> $pointer = Ptr::fromAddress(2);
        if ($pointer != null) {
            echo $pointer->read();
        }
    }
}
```
