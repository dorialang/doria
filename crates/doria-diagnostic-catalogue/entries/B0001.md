# Code Generation Or External Tool Step Failed

Title: varies
Family: compiler

## Explanation

The program passed checking, and a later step of the build could not finish. This is the general code for a failure in code generation, in linking, or in writing the output, used when no more specific code applies.

The usual causes are outside the program. The linker could not be started or reported an error, the Doria runtime library could not be found, the output file could not be written, or `--release` was given to a `doriac` that has no release support. A failure inside code generation itself is a defect in the compiler.

The report shows the family title and keeps the full text of the failure in the developer details. When one source file is compiled, a `Note` repeats the first line of that text.

## Fix

Read the full failure. Run the command again with `--diagnostic-format json` and read the `developerDetails` field, or set `DORIA_DIAGNOSTIC_DEBUG=1` to print it in the report.

When it names the linker, install a C toolchain so that `cc` is available, or set the `CC` environment variable to the linker to use. On Windows, install the Visual Studio C++ build tools or run `doriac` from a Visual Studio developer shell. When it says the runtime library was not found, reinstall the Doria toolchain, or set `DORIA_RT_PATH` to a runtime library built for this compiler. When it names the output file, choose an `--out` path that can be written. When it says release support is not available, compile without `--release` or install a `doriac` that includes it.

When it describes code generation itself, reduce the program to the smallest file that still shows the error and report it to the Doria project with the JSON output.

## Example

No program raises this code on demand: it depends on the machine and the tools installed on it, so one program builds on one machine and fails on another. A user meets it when compiling or running a valid program, for example on a machine where no linker is installed.
